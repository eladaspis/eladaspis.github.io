Transformers have completely revolutionized Natural Language Processing (NLP) and Computer Vision. But what about audio? Models like OpenAI’s Whisper, AST (Audio Spectrogram Transformer), and HuBERT have proven that the Transformer architecture is exceptionally powerful for audio processing tasks, including speech recognition, sound classification, and music generation.

In this post, we will build a Transformer for audio from scratch. We’ll cover the core mathematics, the intuition behind processing sound waves, and implement the complete architecture in PyTorch.

Key Milestones: How Transformers Transformed Audio AI

Before diving into the implementation, it helps to understand how the Transformer architecture evolved to handle sound across different domains. Researchers adapted attention to audio in three distinct paradigms:

Model / Paper Year Domain / Task Input Representation Key Architectural Innovation
Music Transformer (Huang et al.) 2018 Symbolic Music Generation MIDI Events Relative positional self-attention for long sequences
Wav2Vec 2.0 (Baevski et al.) 2020 Self-Supervised Speech Raw 1D Waveform 1D CNN + Transformer encoder with Gumbel-VQ contrastive loss
Conformer (Gulati et al.) 2020 Speech Recognition (ASR) Mel-Spectrogram Interleaved depthwise convolutions + self-attention
AST (Gong et al.) 2021 Audio Event Classification 2D Mel-Spectrogram Patches Pure ViT architecture applied directly to spectrogram patches
HuBERT (Hsu et al.) 2021 Self-Supervised Representation Mel / Raw Waveform Offline k-means pseudo-labeling with BERT-style masked prediction
SepFormer (Subakan et al.) 2021 Source Separation Time-domain learned frames Dual-path Transformer (short-term & long-term attention)
Whisper (OpenAI, Radford et al.) 2022 Multilingual Speech-to-Text 80-channel Mel-Spectrogram Large-scale weakly supervised Encoder-Decoder Transformer
MusicGen & VALL-E (Meta / MS) 2023 Audio & Speech Generation Discrete Codec Tokens (EnCodec) Multi-codebook delay interleaving & AR+NAR cascades

1. Classification & Representation: AST & HuBERT

  • AST (Audio Spectrogram Transformer): Showed that audio classification does not require specialized 1D CNNs or RNNs. By converting a Mel-Spectrogram into a grid of 2D patches (just like Vision Transformers process images), AST established SOTA performance on benchmarks like AudioSet and ESC-50.
  • HuBERT & Wav2Vec 2.0: Solved the lack of labeled audio data by introducing self-supervised pre-training. HuBERT uses offline k-means clustering to turn continuous acoustic frames into discrete target units, training the Transformer to predict masked tokens similar to BERT in NLP.

2. Speech Recognition & Perception: Whisper & Conformer

  • Conformer: Combined the local feature-extraction power of CNNs with the global context of Transformers, creating the standard architecture for modern speech-to-text engines.
  • OpenAI Whisper: Demonstrated that scaling a standard Encoder-Decoder Transformer with simple Mel-Spectrogram inputs over 680,000 hours of weakly supervised web data yields human-level speech transcription and translation robustness across languages.

3. Generation & Separation: MusicGen, VALL-E & SepFormer

  • SepFormer: Applied dual-path self-attention to separate overlapping speakers or instruments in the time domain without losing phase relationship.
  • MusicGen & VALL-E: Transformed audio generation from raw sample synthesis into discrete language modeling by quantizing audio into multi-stream neural codec tokens (EnCodec / DAC) and predicting them using delayed causal attention patterns.

How Do We Feed Audio to a Transformer?

Unlike text, which is naturally discrete (words/tokens), audio is a continuous 1D signal (a waveform). While some models (like Wav2Vec 2.0) process raw waveforms directly, it is often much more efficient to convert the audio into a 2D representation: the Mel-Spectrogram.

The Math: Short-Time Fourier Transform (STFT)

To create a spectrogram, we apply the STFT. We take a window function \(w(n)\) of length \(N\), slide it across the audio signal \(x(n)\), and compute the Discrete Fourier Transform (DFT) for each window:

\[ X(m, \omega) = \sum_{n=-\infty}^{\infty} x(n) w(n - m) e^{-j\omega n} \]

Where:

  • \(m\) is the time frame index.
  • \(\omega\) is the frequency bin index.

We then map these frequencies to the Mel scale, which mimics human hearing (being more sensitive to pitch changes at lower frequencies), resulting in our Mel-Spectrogram \(S \in \mathbb{R}^{F \times T}\), where \(F\) is the number of frequency bins and \(T\) is the number of time frames.

Patching the Audio (Like ViT)

A Mel-Spectrogram is effectively a 2D single-channel image! We can borrow the core idea from the Vision Transformer (ViT). Instead of processing pixel by pixel, we divide the spectrogram into a grid of non-overlapping patches.

Given a spectrogram \(S \in \mathbb{R}^{F \times T}\), we divide it into patches of size \(P_F \times P_T\). The total number of patches \(N\) is:

\[ N = \frac{F}{P_F} \times \frac{T}{P_T} \]

Each patch is flattened into a 1D vector and passed through a linear layer (a linear projection) to create patch embeddings of dimension \(D\).

PyTorch Implementation: Audio Patch Embedding

import torch
import torch.nn as nn

class AudioPatchEmbedding(nn.Module):
    def __init__(self, in_channels=1, embed_dim=768, patch_size=(16, 16), stride=(16, 16)):
        super().__init__()
        # We use a 2D convolution with kernel_size == patch_size and stride == patch_size
        # to effectively extract non-overlapping patches and project them to embed_dim.
        self.proj = nn.Conv2d(in_channels, embed_dim, kernel_size=patch_size, stride=stride)

    def forward(self, x):
        # x shape: (Batch, Channels, Freq, Time)
        x = self.proj(x)      # Shape: (Batch, embed_dim, Freq_patches, Time_patches)
        x = x.flatten(2)      # Shape: (Batch, embed_dim, Num_Patches)
        x = x.transpose(1, 2) # Shape: (Batch, Num_Patches, embed_dim)
        return x

Positional Encoding

Unlike RNNs or CNNs, Transformers have no built-in sense of order or position. Since an audio clip has a strict temporal and frequency structure, we must inject positional information into our patch embeddings.

The classic sinusoidal positional encoding is defined as:

\[ PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right) \] \[ PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right) \]

Let’s implement a learnable positional embedding for simplicity, which is standard in modern audio transformers like AST.

class AudioTransformerEmbedding(nn.Module):
    def __init__(self, in_channels=1, embed_dim=768, patch_size=(16, 16), num_patches=1200):
        super().__init__()
        self.patch_embed = AudioPatchEmbedding(in_channels, embed_dim, patch_size)
        
        # Learnable positional embeddings plus a CLS token for classification tasks
        self.cls_token = nn.Parameter(torch.zeros(1, 1, embed_dim))
        self.pos_embed = nn.Parameter(torch.zeros(1, num_patches + 1, embed_dim))

    def forward(self, x):
        B = x.shape[0]
        x = self.patch_embed(x)
        
        # Prepend CLS token
        cls_tokens = self.cls_token.expand(B, -1, -1)
        x = torch.cat((cls_tokens, x), dim=1)
        
        # Add positional embedding
        x = x + self.pos_embed
        return x

The Self-Attention Mechanism

This is the heart of the Transformer architecture. For every patch (token), the model computes a Query (\(Q\)), Key (\(K\)), and Value (\(V\)).

The Scaled Dot-Product Attention computes how much focus a given audio patch should place on every other patch in the spectrogram:

\[ \text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V \]

For example, a patch containing a sharp transient (like a drum hit) might attend strongly to the subsequent ringing frequencies to understand the full acoustic context.

Putting It All Together: The Audio Transformer

Let’s stack the standard Transformer Encoder blocks on top of our embeddings. We will output the final representation of the [CLS] token to classify the audio (e.g., “Dog barking” vs “Car horn”).

class AudioTransformer(nn.Module):
    def __init__(self, num_classes=10, embed_dim=768, depth=12, num_heads=12, num_patches=80):
        super().__init__()
        # 1. Embed the spectrogram
        self.embeddings = AudioTransformerEmbedding(
            embed_dim=embed_dim, 
            num_patches=num_patches
        )
        
        # 2. Transformer Encoder
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=embed_dim, 
            nhead=num_heads, 
            dim_feedforward=embed_dim * 4, 
            activation='gelu',
            batch_first=True
        )
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers=depth)
        
        # 3. Classification Head
        self.mlp_head = nn.Sequential(
            nn.LayerNorm(embed_dim),
            nn.Linear(embed_dim, num_classes)
        )

    def forward(self, x):
        # x: (Batch, 1, Freq, Time)
        x = self.embeddings(x)
        
        # Pass through Transformer
        x = self.transformer(x)
        
        # Extract the [CLS] token representation (index 0)
        cls_output = x[:, 0]
        
        # Classify
        out = self.mlp_head(cls_output)
        return out

# --- Let's test the model! ---
if __name__ == "__main__":
    # Dummy Mel-Spectrogram: Batch size 2, 1 channel, 128 Mel-bins, 160 time frames
    dummy_audio = torch.randn(2, 1, 128, 160) 
    
    model = AudioTransformer(num_classes=10, num_patches=80)
    output = model(dummy_audio)
    
    print("Model initialized successfully!")
    print(f"Input shape:  {dummy_audio.shape}")
    print(f"Output shape: {output.shape}")

Conclusion

By treating audio spectrograms as images and chopping them into patches, we can seamlessly apply the standard Transformer architecture to sound! This approach (AST) holds state-of-the-art records on benchmarks like AudioSet.

In a production scenario, you would want to add features like causal masking (if you are generating audio or doing real-time streaming) and dynamic padding. But the core concept remains beautifully simple.
