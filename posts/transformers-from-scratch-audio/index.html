Building a Transformer for audio from scratch requires a fundamental shift in how we think about the input data. The original Transformer architecture was designed to process discrete tokens (like words or subwords in NLP). However, raw audio is a continuous waveform with tens of thousands of samples per second.

In this comprehensive guide, we will walk through the construction of an Audio Spectrogram Transformer (AST) from scratch using PyTorch. We will cover feature extraction, patch embedding, positional encoding, and the integration of standard Transformer blocks.

1. Feature Extraction: Spectrograms

If we feed raw audio (e.g., 16 kHz sampling rate) directly into a standard self-attention mechanism, the \(\mathcal{O}(N^2)\) computational complexity would instantly exhaust GPU memory. A one-second clip would result in an attention matrix of \(16,000 \times 16,000\).

To solve this, we rely on time-frequency representations. By using libraries like torchaudio, we convert the 1D raw waveform into a 2D Mel-Spectrogram. This process treats the audio essentially as an image where the X-axis is time, the Y-axis is frequency (binned into Mel-scale bands mimicking human hearing), and the pixel intensity is the amplitude.

2. Patch Embeddings: Audio "Tokens"

In NLP, a word is mapped to a vector via an embedding dictionary (nn.Embedding). For our 2D Mel-Spectrogram, we borrow a technique from Vision Transformers (ViTs): Patch Embedding.

We divide the spectrogram into small, non-overlapping patches (e.g., \(16 \times 16\) pixels). Each patch represents a small slice of frequencies over a short window of time. We use a 2D Convolutional layer (nn.Conv2d) with a stride equal to the kernel size to linearly project each patch into a dense vector of size \(d_{model}\). These vectors serve as our sequence of "audio tokens".

3. Positional Encoding for Audio

Transformers process all patches simultaneously; they have no inherent concept of time or frequency order. If we shuffle the patches, the self-attention output is identical but shuffled.

To retain the sequential and spatial structure of the audio, we add a Positional Encoding vector to each patch embedding. In Audio Transformers, this is often a learnable parameter matrix (nn.Parameter) initialized with zeros or standard sinusoidal encodings. This allows the model to differentiate a low-frequency sound at the beginning of the clip from a high-frequency sound at the end.

4. The Transformer Encoder

Once we have a sequence of positionally-aware audio patches, they are passed into the standard Transformer Encoder. The core components here are:

  • Multi-Head Self-Attention: This allows the model to mix information across the entire audio clip. For example, one attention head might learn to track the fundamental pitch over time, while another head tracks the rhythmic percussion patterns.
  • Feed-Forward Networks (FFN): After attention mixes the features across patches, the FFN (using GELU activations) processes each patch's features individually, projecting them into a higher-dimensional space to learn complex acoustic representations.

5. Full PyTorch Implementation

Below is a complete, from-scratch implementation of an Audio Spectrogram Transformer in PyTorch. Notice how we use nn.Conv2d for the patch embedding and standard nn.TransformerEncoderLayer for the processing.


import torch
import torch.nn as nn
import torchaudio

class AudioSpectrogramTransformer(nn.Module):
    def __init__(self, embed_dim=768, num_heads=12, depth=12, patch_size=(16, 16), in_chans=1, num_classes=50):
        super().__init__()
        
        # 1. Patch Embedding Layer
        # We treat the spectrogram like a 1-channel image. 
        # A Conv2d layer slices it into non-overlapping patches and projects to embed_dim.
        self.patch_embed = nn.Conv2d(
            in_channels=in_chans, 
            out_channels=embed_dim, 
            kernel_size=patch_size, 
            stride=patch_size
        )
        
        # 2. Positional Encoding
        # Since audio sequences vary in length, we typically define a max sequence length
        # or interpolate the position embeddings for longer sequences.
        self.cls_token = nn.Parameter(torch.zeros(1, 1, embed_dim))
        # Assuming max 1024 patches
        self.pos_embed = nn.Parameter(torch.zeros(1, 1024 + 1, embed_dim))
        
        # 3. Transformer Encoder Block
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=embed_dim,
            nhead=num_heads,
            dim_feedforward=embed_dim * 4,
            activation="gelu",
            batch_first=True
        )
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers=depth)
        
        # 4. Classification Head (for tasks like audio classification)
        self.mlp_head = nn.Sequential(
            nn.LayerNorm(embed_dim),
            nn.Linear(embed_dim, num_classes)
        )

    def forward(self, x):
        # x input shape: [Batch, Channels=1, Freq=128, Time=1024] (Mel-Spectrogram)
        
        # Patch embedding: [Batch, embed_dim, Freq/16, Time/16]
        x = self.patch_embed(x) 
        
        # Flatten spatial dimensions: [Batch, embed_dim, Num_Patches]
        x = x.flatten(2)
        
        # Transpose for transformer: [Batch, Num_Patches, embed_dim]
        x = x.transpose(1, 2)
        
        # Append classification token
        B = x.shape[0]
        cls_tokens = self.cls_token.expand(B, -1, -1)
        x = torch.cat((cls_tokens, x), dim=1)
        
        # Add positional embedding
        x = x + self.pos_embed[:, :x.shape[1], :]
        
        # Pass through Transformer
        x = self.transformer(x)
        
        # Classification using the CLS token
        cls_out = x[:, 0]
        out = self.mlp_head(cls_out)
        
        return out

# Example usage:
# Create a dummy batch of 2 Mel-spectrograms: [Batch=2, Channels=1, Freq=128, Time=1024]
dummy_audio_features = torch.randn(2, 1, 128, 1024)
model = AudioSpectrogramTransformer()
predictions = model(dummy_audio_features)
print("Output shape:", predictions.shape) # Expected: [2, 50] (logits for 50 classes)

This architecture is highly effective for tasks like audio classification (e.g., environmental sound classification, keyword spotting). By prepending a learnable [CLS] token, we aggregate the global audio context into a single vector, which is then passed through an MLP to generate class logits.
